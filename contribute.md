# 🤝 Contribution Guidelines

Welcome to our learning community!

This repository is not just about writing code or completing daily tasks. It is about learning together, understanding concepts, improving problem-solving skills, and helping each other grow as developers.

Please read these guidelines before contributing.

## 📚 1. Start with the Issues

We have created GitHub Issues for daily learning tasks.

Each issue contains:
- 📖 Learning materials and concept explanations.
- 💡 Topics you should understand.
- 💻 Practical coding assignments.
- 🎯 Expected outcomes.

**Before starting any task, make sure you carefully read the corresponding issue and understand what is expected.**

Don't just jump into coding. Understand the concepts first.

## 🚫 2. No Vibe Coding

This community is created for learning, not just producing code.

- Avoid blindly generating code using AI tools.
- Don't copy-paste solutions without understanding them.
- Try solving problems independently first.
- Understand every line of code you submit.
- Be prepared to explain your approach during code reviews.

You can use AI as a learning assistant to understand concepts, debug errors, and explore alternative approaches.

**The goal is to develop your own problem-solving abilities, not depend on AI to do the thinking for you.**

## 💻 3. How to Contribute

Follow these steps for every daily task.

### Step 1: Check GitHub Issues
- Visit the repository's Issues section.
- Find the relevant daily task.
- Read the learning material and practical requirements.
- Ask questions if anything is unclear.

### Step 2: Clone the Repository

Clone the project to your local machine:

```bash
git clone <repository-url>
cd <repository-name>
```

### Step 3: Create Your Branch

Create a separate branch for your task.

Use the following naming convention:

```bash
git checkout -b your-name/day-01-task-title
```

Example:

```bash
git checkout -b shubham/day-01-javascript-basics
```

Please maintain this naming convention for consistency.

### Step 4: Complete the Task

- Follow the instructions mentioned in the issue.
- Write clean, readable, and maintainable code.
- Add comments wherever necessary.
- Test your implementation.
- Make sure you understand your solution.

### Step 5: Commit Your Changes

Use meaningful commit messages.

Example:

```bash
git add .
git commit -m "feat: complete day 01 javascript basics"
```

### Step 6: Push Your Branch

```bash
git push origin your-name/day-01-task-title
```

### Step 7: Create a Pull Request

- Open the repository on GitHub.
- Click on **Compare & Pull Request**.
- Select `main` as the base branch.
- Select your task branch as the compare branch.
- Provide a meaningful PR title and description.
- Mention the related issue using `Closes #ISSUE_NUMBER` where applicable.
- Submit your Pull Request.

## 🔍 4. Code Review & Merging

Once you raise a Pull Request:

1. Maintainers will review your implementation.
2. We will check code quality, correctness, readability, and your understanding of the solution.
3. If changes are required, we will provide feedback.
4. Make the necessary improvements and push the updates.
5. Once everything looks good, your PR will be approved and merged.

**Please remember:** Creating a PR does not automatically mean it will be merged. We want to maintain code quality and ensure everyone is learning the right concepts.

## 🙋 5. Ask Questions & Help Others

This is a community, not a competition.

- Stuck on a problem? Ask a question.
- Found something confusing? Start a discussion.
- Know the solution to someone's problem? Help them.
- Have a better approach? Share your thoughts.
- Found a bug or improvement? Raise an issue.

Never hesitate to ask questions. There is no such thing as a silly question when you are learning.

We encourage everyone to participate, discuss solutions, review code, and share knowledge.

## ❤️ 6. Our Community Principles

A few things we believe in:

- **Learning over competition:** This is not a race.
- **Consistency over speed:** Small improvements every day matter.
- **Understanding over completion:** Completing a task without understanding it defeats the purpose.
- **Collaboration over individual growth:** Help others grow along with you.
- **Quality over quantity:** Focus on writing good code, not just more code.

---

### 🚀 Final Note

Don't worry about how quickly someone else is progressing.

Everyone has a different learning pace, background, and experience level.

Take your time, understand the concepts, practice consistently, and help others whenever possible.

**We are here to become better developers together, not to compete with each other.**

Happy Learning & Happy Coding! 💻
